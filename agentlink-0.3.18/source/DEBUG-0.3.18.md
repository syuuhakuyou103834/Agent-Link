# AgentLink 0.3.18 故障处理与证据说明

## 0.3.17 上下文超限

确认原因是统一对话把 `messages[].turn` 中的工具输出、重复正文、blocks 等一并序列化。原始测试发送上下文 319,519 字符，超过 280,000 字符的应用限制；386,582 JSON 字节尚未超过字节限制。不是 SMB 文件大小限制，也没有证据证明是模型 token 窗口耗尽。

0.3.18 将模型输入与完整存档分离。本机回放保留全部 16 条消息正文和 26 条工具记录；正文及索引 14,048 字符，完整 B 补充请求 14,810 字符、26,718 JSON 字节。路径长度不同会使数字略有变化。

## 恢复顺序

1. 退出两端旧版，解压 0.3.18 到新目录。保留原数据、共享目录、项目目录与快照。
2. 两端启动新 AgentLink.exe 并连接原共享目录，核对标题和左下角都是 0.3.18。
3. 选择原中断任务，在 A 或 B 输入“继续”。用户原先交 B 的消息仍由 B 处理；正式流程等待补充处理结束。
4. 查看任务时间线、对话轮数和展开详情。已完成步骤在恢复场次中继承，原场次仍可追溯；模型请求只用于未处理消息及后续未完成步骤。
5. 若提示版本、角色锁、原步骤范围或会话归属不符，先处理明确错误，再输入“继续”。不要手改 claim、call、meta 或实例标识，也不要删除锁文件冒充执行者退出。

本机模拟已覆盖两端重启、A/B 任一端发出继续、原 B 补充保留及 A/B 完成结果不重跑。真实 B/SMB/模型恢复仍需现场验收。升级不恢复账号额度。

## 查看输入与完整证据

- 主界面“展开详情 → 任务与快照”：本机输入字符/JSON 字节、完整正文外置序号、索引路径、SHA-256 和阻塞详情。
- 本机数据根目录 `context-evidence/<对话ID>/<内容哈希>/index.json`：消息与工具记录文件索引。
- `message-*.json`：消息的完整发送正文和来源；`turn-*.json`：此前保存的完整结果对象，包括软件捕获的工具输出。
- 本机 `conversations/<ID>/context-view-A.json` 或 B.json：最近一次构造/检查回执。正式 call 台账及聊天 attempt 中保存对应发送视图回执。
- 工具事件本身沿用原来的单条捕获长度限制；本次未声称恢复历史上未捕获的工具输出。

索引 SHA-256 口径：UTF-8 JSON，键排序，分隔符逗号/冒号，`ensure_ascii=False`。它是规范化内容哈希，不是带缩进 JSON 文件的原始字节哈希。文件缺失、损坏或内容与已有证据不一致时拒绝继续覆盖；不要把读取失败当作空证据。

## 仍然超限或中断

正文外置仅用于较早的普通答复，保留用户约束、未处理消息、未决审查及最近消息。必要内容仍超限时会明确阻塞，列出阶段与实际数字，不领取正式步骤、不发送模型请求。完整历史不会自动清空。要采用较短的新任务，请先整理可审查的交接说明，再明确停止原任务并在 A 新建对话。

额度、认证、运行组件、权限、共享读写故障仍按各自错误处理。本版没有开放完全访问、自动审批、跨机器远程执行或模型自动重发。共享 JSON 文件仍有独立的存储大小限制；不保证任意长度对话或任意大工具日志都能无限保存。

## 本机复测

```powershell
python tests/test_context_view.py
python tests/test_context_workflow.py
python tests/test_context_ui.py
python tests/run_release_checks.py
```

上面均为本机测试或模拟模型。`check_unified_preflight.py` 仅验证本机已安装 Codex 接受包含证据目录的权限配置，不发送模型请求，也不证明 OS 文件读写隔离已实测。

原始私有失败记录可用 `tests/replay_context_fixture.py <冻结JSON> <全新输出目录>` 回放。该脚本会在隔离目录保存私有材料；跨机或公开交付只取 `metrics.json`，不要把真实对话和 RPC 日志混入公开证据包。
