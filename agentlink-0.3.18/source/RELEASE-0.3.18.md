## 2. 本次变化与范围

对应 `docs/BUSINESS-REQUIREMENTS.md` 的 BR-018 / AC-018-01～06。仅修复本次上下文与恢复路径；用户没有授权本轮扩大到 A01～A05/B01 的其他审查问题。

1. **修复重复输入。** `messages[].turn` 里的工具事件、重复 answer/blocks、usage 等不再整包嵌入模型请求。完整存档仍保留；用户正文、来源、目标、确认、pending 和轮数进入发送视图。
2. **新增只读证据索引。** 每个节点在本机生成消息/结果文件和规范化 SHA-256 索引；模型只增加该专用目录的读权限。B 读取自己接收的记录，不访问 A 的额外路径。收到证据不等于已独立验证。
3. **完整正文外置。** 接近发送预算时，较早普通答复转为明确文件引用，不编造摘要、不截断原始内容。用户要求、pending、最近四条消息，以及标记为 blocked/changes_requested 的审查正文保守保留。详情显示哪些消息外置。
4. **精确预发送阻塞。** 明确显示阶段、实际字符/JSON 字节、各自限制和未发送状态。预算保持 280,000 字符与 950,000 JSON 字节；聊天在尝试前检查，正式文字/源码步骤在 claim 与模型请求前检查。
5. **修复继续时丢失原消息。** 对本版预算阻塞和 0.3.17 同类预发送错误，明确继续只消费恢复指令，保留原 B 补充。两端重启后通过关联恢复继承已完成成果，不重跑已完成 A/B 步骤。版本检查失败仍保留原消息。
6. **兼容与诊断。** 双方必须声明本版上下文证据能力才能正式执行。GUI 新增预算状态和详情；保留单一输入、grill-me 澄清、A 发起/B 审查、源码快照、轮数、方向补充及原权限规则。

没有删除业务功能。移除的是模型输入中重复的内部结果对象和重复“之前结果”正文；完整记录、工具展示和用户可读时间线继续保存。未新增模型自动摘要、增量源码同步、GitHub 自动上传、自动审批或额度重置。

## 5. 限制与未验证事项

- 不是无限上下文。必要正文仍可能超限；共享 JSON 有独立大小限制。不会自动丢弃用户约束或以不完整材料继续。证据随对话增长占用本机空间，本版未新增自动清理。
- 工具文件保存的是软件此前捕获的结果；原单条输出捕获限制保持不变，无法补回未捕获日志。外置正文需模型实际读取后才算阅读；本轮没有用真实模型证明其阅读行为。
- 保留原权限限制：A 仅在确认项目修改，B 源码只读；真实两机工具权限矩阵与 SMB 故障仍待独立执行。预检接受配置不证明 OS 权限全部实测。
- 原始 A01～A05/B01 的其他清理、创建事务、历史授权等问题不计入本版已修复项。
- 只验证了隔离模拟升级/恢复。实际用户历史、原会话归属、B 本机运行组件与现场共享状况仍可能使恢复阻塞；不能据本报告强行修改执行锁或场次状态。
