# 0.3.2 讨论连续性修复

## 原因

历史选择只改变 UI 快照；start 命令原本只有 topic 和 rounds。新场次、新本机 thread 没有带入所选历史。首轮还固定要求“提出具体方案”，会使执行请求再次退回计划。

## 修复

- 已完成记录的默认操作改为“继续讨论”，显示承接来源；“新建讨论”清空关联。异步历史读取期间禁止提交，过时 UI 快照不重新附加旧记录。
- 新场次记录父场次及 context.json 的 SHA-256。复制历史用户议题、补充和双方完成答复，继承更早快照；不附原始工具日志、内部思考或账号配置。
- 发起方和接收方每次输入带同一完整快照；接收方核对快照与请求是否一致。不依赖跨账号 thread 恢复或模型主动查找工作区。
- 重启后从所选已完成场次生成承接数据。旧场次不改写；失败、停止、缺失或损坏历史不自动当作最终结论。
- 双方心跳声明 continuation-v1；续接前检查对端支持。历史上限 120000 字符，单次请求另有传输预算；超限显式失败，不静默截断，不增加模型总结调用。
- 初稿、评审提示尊重用户的执行要求，并要求区分实际证据和他方陈述；历史不授予额外权限。

## 验证入口与边界

- tests/test_context.py：快照、笔记、完整答复、链式继承、独立新讨论、缺失/篡改/超长/非完成历史。
- tests/test_system.py：本机两个独立模拟接口，包括重启后反向续接、多次续接、精确请求数和无历史泄漏。
- tests/test_gui.py：实际 PyQt 控件的续接入口、来源提示、上下文查看、新建脱离和异步选择。
- tests/test_storage.py：保留 SMB I/O 修复的 Windows 文件操作回归。
- tests/test_windows_startup.py：真实 Windows Qt 插件渲染。

这些脚本的模拟接口不调用真实模型。执行结果另见交付的 VERIFICATION-0.3.2.json；真实双机、双账号、GUI 模型续接仍需双方更新后验证。
