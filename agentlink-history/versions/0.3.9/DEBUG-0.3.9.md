# 0.3.9 执行归属清理修复

0.3.8 清理失败会阻止本机请求，但 run_initiator 释放 discussion.lease 后，对端仍可能获准创建新场次。本机故障注入已复现准入缺口。

0.3.9 用独立共享 execution.lease 覆盖 _perform。cleanup_pending 时保留该锁，只有确认清理成功才释放。双方发起新场次前探测该锁；disconnect 先清理服务、再释放执行归属、最后释放角色锁。终态已提交时仍向 UI 报告清理错误，终态不变。

新协议能力 agentlink-execution-lease-v3 要求双方使用 0.3.9；旧版无法获得本修复保障，旧版发起的历史混版失败不改判。只有新节点在场不能阻止未升级旧节点的所有行为。

两项端到端离线故障测试分别注入发起端/接收端 TerminateJobObject 失败，验证真实模拟服务仍在、句柄和角色锁保留、双方零新增请求、再次清理成功后完整新场次恰好三请求。两项旧迟到事件测试增加先拒绝新请求，再在真实 RPC 已结束后显式释放执行归属的测试屏障；其余迟到回调隔离断言保留。

源码及交付在 A 工作区生成；C:\AgentLink-GUI 未替换，共享上传和真实双机验收尚未完成。
