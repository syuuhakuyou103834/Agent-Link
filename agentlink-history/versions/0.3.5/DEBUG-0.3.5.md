# AgentLink 0.3.5 评审补修候选

在已封存的0.3.4基础上修复两项遗漏，保留既有去重、终态、输入和内存修复。

- 补充要求增加稳定 note_id。同一编号与相同内容重投只追加一次；同一编号不同内容明确拒绝；不同编号的相同文本照常保留。GUI每次新的补充操作产生新编号，不按文本误删用户有意重复的要求。控制记录继续保留旧版 notes 列表供历史承接使用。
- 心跳声明 agentlink-safe-lifecycle-v1 能力。新场次准入及接收方执行入口缺少该能力时拒绝，不创建新场次、不领取步骤、不启动本机模型。兼容规则按安全能力声明，不要求未来所有补丁版本号完全相同。

必须双方更新并连接。实测混合0.3.4与0.3.5的两种角色组合：新版发起时双方零请求；旧版发起时旧版仍先调用初稿一次，新版接收方零请求。升级一台不能让未修改的旧版新增前置检查。因此混版“整场零请求”验收失败，不能在生产共享目录混用。

本次新增覆盖：同补充编号重投/不同编号同文、双方重复继续、停止后继续、旧场次错误延迟返回、请求前取消、发布成功但确认丢失、旧能力拒绝、反复失败后下一场恢复。恢复采用保守停止，不自动重试模型；已有结果可以留在本机或共享中，不伪装整场完成。

失败恢复基线：预热3对、测量9对，超时/停止/发布失败循环各4次，每次失败后跟随一次正常单轮；共24场、48次模拟请求。首末各3个测量对的资源中位数增长阈值20%；资源包含本机两服务线程所在进程与两个当前模拟子进程。原0.3.4正常耐久110场证据另列，不转记为本版本实测。

本次离线模拟和本机启动证据不代表真实双机/SMB/实际沙盒/硬崩溃验收。受测源码与ZIP哈希见工作区 followup-20260910 报告。旧版本和旧证据未覆盖。
