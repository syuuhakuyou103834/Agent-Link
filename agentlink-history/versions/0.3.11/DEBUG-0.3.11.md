# 0.3.11 验证边界与排错

本轮新增项目绑定、完整快照、原子发布、哈希核验、固定 A/B 角色、结构化审查、只读最终总结、项目问题记录及最多 7 次调用约束。回归结果见发行目录 RELEASE-0.3.11.md。

## 已实测的真实接口阻塞

本机执行 `thread/start`，未执行 `turn/start`，模型请求数为 0。命名权限配置触发以下真实错误：

```
windows unelevated restricted-token sandbox cannot enforce split filesystem read restrictions directly; refusing to run unsandboxed
```

这说明当前执行环境无法实施所需读取隔离。接口拒绝执行属于正确的阻塞行为，不是权限隔离验收通过。没有自动降级、配置管理员权限、改变系统 ACL、替换用户登录或绕过沙盒。真实双机部署需要在两机各自获准且支持此权限配置的 Codex Windows 环境重新验证。

配置确认检查只能证明接口接受了指定配置；实际文件写入拒绝与跨目录读取拒绝仍须实测，不能根据界面文字或模拟响应宣称已经隔离。命名权限文档：https://learn.chatgpt.com/docs/permissions 。本次使用本机 Codex 生成的 experimental JSON Schema 核对 permissions、config、activePermissionProfile 和 outputSchema 字段。

## 故障处理

快照缺少 ready、ZIP/清单哈希不符、文件集合不符、越界路径、同名别名、重解析点和既有镜像变化均阻塞。原始暂存目录保留作诊断，不自动删除用户内容。失败后不会重发已领取步骤；请查看实际请求台账及日志，在故障解决后新建场次。

A 在 B 审查期间如果被其他工具或用户修改，下一步会检测到与已交付快照不一致，阻止宣称最终通过。它不是针对所有桌面进程的系统级文件锁。

B 的临时测试目录中不得复制出另一份可修改的“正式源码”用于代替评审：原有源码与测试必须在只读快照上检查，证据要注明临时辅助测试。必要的依赖由用户在本机项目设置中明确配置，缺失依赖写入阻塞原因。

## 开发中复现并修复

- 首份能力心跳尚未发布就宣布节点连接成功，导致立即发起被拒绝。现在心跳先发布，再报告连接成功。
- Windows 长路径导致深层快照临时清单创建失败。存储及交付 I/O 使用扩展路径写法，新增超过 260 字符的文件往返检查。
- B 通过不能替代双方一致：A 的只读总结也绑定快照并显式确认；A 保留分歧时转交用户裁决。
- 源码清单使用快照哈希作为本机文件名，两端 GUI 指向同一版本的可核验清单。
