# Errno 13 / SMB 并发访问修复记录

日期：2026-09-10。问题发生在 B 读取共享目录 `nodes/A.json` 时。

## 检查与结论

检查时该文件可正常读取，其 ACL 包含 Everyone FullControl，没有发现该文件的持续拒绝访问规则。这个观察不能倒推截图当时所有进程的句柄状态，但不支持直接把问题归因于账户没有读权限。

0.3.0 用普通 Python 文件读取，同时通过 `os.replace` 不断发布心跳。Windows 的原子替换需要删除/重命名访问；CRT 默认读取句柄没有启用删除共享。只要替换访问与读取重叠，就可能得到 PermissionError，errno=13。单独的 Windows 回归测试持有 DELETE 访问而不实际删除文件，准确复现旧版读取的 errno=13；新版读取成功。

在真实 `\\192.168.1.108\shared` 下新建隔离的诊断目录，并发测试还复现了 23 次写入端 errno=13 / WinError=5。仅修改读取句柄和增加重试仍不足以通过高频并发测试。对同一个 JSON 文件的读取和发布增加共享字节范围互斥后，最终压力测试通过。

Windows 共享模式与 delete-pending 行为见 [Microsoft CreateFileW 文档](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。

## 修改

- 每个 JSON 使用稳定的 `.文件名.io.lock`。持锁范围仅覆盖读取或写完后发布，不覆盖模型调用。进程退出自动释放锁；不删除锁文件，以免不同进程锁住不同文件对象。
- Windows 读取使用 READ/WRITE/DELETE 共享模式，不修改文件 ACL，不提高读权限。
- 同时保留临时文件写完再原子发布和有限重试；锁等待最多 5 秒，普通冲突重试预算 1.5 秒。系统自身阻塞的文件调用耗时不受这个重试计时器限制。
- 发布失败保留旧 JSON，并清理本次未发布的临时文件。
- 持续错误仍报出；记录本机错误日志，恢复后清除对应的共享访问警告，不清除无关模型错误。
- 发布 0.3.1 独立免安装 ZIP。双方必须更新，新旧版本混跑不能提供双方遵守互斥的保证。

## 验证

- Windows 文件 I/O 回归：6 项通过，覆盖原版 errno=13、短暂冲突恢复、持续权限拒绝、失败发布保留旧值、互斥和损坏 JSON。
- 真实 SMB 并发测试：154 次成功写入、805 次成功读取，错误 0，中文内容一致性错误 0。
- 真实 SMB 上两节点服务流程：4 项通过；A 发起两轮、B 发起并由 A 暂停/补充/继续、对方中止、错误传递及节点重复锁保护。
- 两节点使用离线模拟模型接口。测试没有调用用户模型或消耗模型额度，也不是在 B 上远程运行真实 GUI；B 的实际账户和 GUI 运行需更新后复核。

本次检查没有修改共享权限、Windows 防火墙或登录凭据。旧讨论和设置保留。
