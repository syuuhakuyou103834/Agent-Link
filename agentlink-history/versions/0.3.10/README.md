# AgentLink GUI 0.3.10

本版在 0.3.9 的进程归属、共享执行锁和实例绑定保护基础上，恢复 0.3.4 的无时限等待、活动状态同步、未完成输出导出及协议 2 历史续接。旧设置自动迁移，无需手工删除超时字段。双方必须使用 0.3.10 或支持同等无时限执行归属能力的版本。详见 `DEBUG-0.3.10.md`；本机测试不能替代真实双机验收。

这是基于 PyQt5 的双机 Codex 协作程序。应用内置 Python 3.13，Windows 10/11 x64 可直接安装，不需要安装 pip 包。每台电脑仍需有已登录、支持 App Server 的 Codex。本版按本机 Codex 0.153.4 协议开发。

## 使用

### 从 0.3.4 / 0.3.9 等版本更新（免安装 ZIP）

两台电脑都退出旧版 AgentLink GUI，将 `AgentLink-GUI-0.3.10-Windows-x64.zip` 完整解压到各自电脑的新目录，双击该目录中的 `AgentLink.exe`。不要直接在 ZIP 内运行，也不要启动旧的桌面快捷方式。界面左下角应为 v0.3.10。

本版会沿用 `%LOCALAPPDATA%\AgentLinkGUI` 中原有设置和讨论历史，不需要重新填写共享目录。A、B 两台都必须更新：新版的短时文件锁需要双方共同遵守，旧版不会使用这些锁。

### 长任务持续等待

- 不限制一次模型任务的总时长；移除原先 900 秒调用上限、20 分钟等待对方上限和新场次的到期时间。
- 设置中原有的“单次调用超时”改为无时限等待说明；旧设置中的 900 秒等数值会自动归零，无需手工编辑。
- 执行节点约每秒向另一节点同步任务阶段、运行时长、最近事件距今多久、是否有工具仍在运行。对方继续等待，不为“继续等”额外调用模型。
- 工具长时间执行会显示“工具执行中，继续等待”；60 秒没有新事件且无在途工具时，显示“进程仍在，暂时无法确认新进展”，继续等待并保留手动停止入口。这是静默提示，不是终止计时器。
- 模型进程真实退出、接口明确返回失败、用户停止/退出程序或持续通信中断仍按错误/停止处理。执行门禁保留 0.3.9 的严格心跳时效、角色锁和实例校验，两机仍需保持系统时间同步；对端记录失效或实例变化时停止且不重发模型请求。共享目录持续故障沿用既有故障处理。
- 连接初始化及非模型管理接口仍有通信超时。外部模型服务或工具自身的限制不由 AgentLink 改写。

新场次使用协议 2（明确的无到期时间），新发起前检查对端具备 `agentlink-execution-lease-v4`，并公布 `unlimited-wait-v1`。协议 1 和 0.3.4 生成的协议 2 已完成历史均可查看和续接。双方更新后再开始新任务；被旧版超时中止的任务不会自动重放。

未完成讨论导出现在会附上已有公开进展和本机任务 ID，并标注“未完成输出”。它们是恢复线索，不会被自动当作已完成结论。

### 继续上一场讨论

0.3.1 的历史列表只用于查看；每次发起都会新建 Codex 任务且不附历史，所以“根据上面结论继续”并不能让模型知道上轮内容。0.3.2 增加显式上下文承接：

1. 双方连接节点。在左侧选择一场**已完成**的讨论（也支持已有 0.3.1 记录）。
2. 输入下一步要求，例如“按上一轮测试集开始测试，5 次调用后给出阶段结果”，选择 2 轮。
3. 检查输入框上方“将继续所选讨论”的来源提示，点击 **继续讨论**。
4. 新场次携带完整的历史议题、用户补充和双方完成答复；更早承接的历史一并保留。双方的“承接上下文”页可查看所用材料。
5. 无关任务先点 **新建讨论**，再输入议题；这样不携带旧历史。运行中的补充仍用“补充到下一轮”。

承接在新场次保存独立 `context.json` 快照并校验 SHA-256，不改写旧讨论，不复制或恢复另一台的 Codex 任务。双方仍创建各自的新任务，但每次请求均明确附带同一份历史，重启后仍可续接。复制历史不额外调用模型；更长的输入会增加 token 用量。

只有已完成记录可自动承接。停止、失败或导入的旧式 TXT 不被当作完整最终结论；可选择前一场已完成记录，或新建讨论并粘贴经确认的材料。缺失、损坏或超过 120000 字符的历史会报错停止，不静默截断。历史不包含原始工具输出、登录资料或内部思考；需要执行证据时，仍需按答复中的证据路径读取实际文件。

双方必须连接且支持此功能（0.3.2 或兼容版本）；旧版对端会触发升级提示。承接不改变任一节点的项目、工具配置或权限。首轮提示也已调整：用户要求测试或实施时，应实际执行获准工作，而非固定再次提出方案。

### 保留的 0.3.1 文件访问修复

修复 SMB 共享目录中的并发读取/替换造成 `Errno 13 / WinError 5`。同一个 JSON 文件用稳定的 `.文件名.io.lock` 做短时互斥；读取句柄允许删除/重命名共享；访问冲突短暂重试，超过上限则保留真实错误。仍使用写完临时文件再发布的方式，避免读到半份 JSON。此重试只针对文件 I/O，不会重复调用模型。

`.io.lock` 文件留在目录中是正常现象；进程退出时操作系统会释放实际锁，不用手工删除。真实、持续的权限错误仍会显示，并写入本机 `logs\agentlink-errors.jsonl`，记录路径、errno、WinError 与调用堆栈。共享访问恢复后，会清除对应的文件访问警告。

### 首次使用

1. 将免安装 ZIP 完整解压到两台电脑各自的本地目录，双击 `AgentLink.exe`。
2. 首次设置中，ZHOUBY 选择 A；WILLDESKTOP 选择 B。
3. 首次设置默认共享目录为 `\\192.168.1.108\shared\AgentLink-GUI-v1`。两边必须一致。程序不保存 SMB 密码；沿用当前 Windows 用户已建立的共享访问。
4. 检查自动找到的 `codex.exe`，保持“沿用本机 Codex 技能和插件配置”和“只读沙盒”，保存后点“连接节点”。
5. 两边在线后，任一台输入议题、选评审轮数、点“发起讨论”。1 轮为初稿→评审→修订，共 3 次调用；2 轮为 5 次调用。双方都能暂停、继续、停止和补充要求。

两台共同处理一场讨论。发起方负责初稿与最终修订，另一方评审。暂停在当前调用结束后生效；停止请求中断正在运行的模型，接口不响应时终止本机 App Server 进程树。失败后保留记录，不自动重发模型请求；新建讨论后可再次尝试。

## 界面

- 讨论现场分 A/B 两列，增量显示回答；对方内容约每秒同步。
- 公开思考摘要只显示接口提供的摘要，不显示完整内部思考。接口未提供时该页留有说明。
- 工具事件显示命令、工具状态和有限长度的输出；原始接口诊断在本机日志。
- 节点能力来自各台 Codex 的技能与 MCP 服务清单；实际可用性仍取决于配置、授权和当前项目。
- 本机项目目录影响项目技能/规则。各台自行选择目录与权限，另一台不能远程提高权限。只读不等于禁用全部外部工具；额外权限请求不会自动批准。
- 用户输入请求暂以运行日志提示，可用“补充到下一轮”传达要求；本版不提供通用工具授权弹窗。
- 导入旧版 `discussion.txt` 可阅读既有记录；导出完整记录为 TXT/Markdown。“实施交接”只生成交接文档，后续在具体项目中执行。

## Codex 桌面界面

本版通过 Codex 本地 App Server 创建各节点独立、非临时的任务，同一节点在一场讨论中复用任务。可复制“Codex 任务 ID”，在对应电脑的 Codex 桌面端请助手打开该本机任务。任务是否直接出现在侧栏取决于桌面端版本和项目列表；本版不修改 Codex 数据库。跨两个账号的完整讨论由 AgentLink 界面汇总，并非原生跨账号群聊。

官方接口说明：https://learn.chatgpt.com/docs/app-server

## 文件与卸载

- 免安装版程序：你解压的目录；旧安装版程序：`%LOCALAPPDATA%\Programs\AgentLinkGUI`
- 设置、历史、日志：`%LOCALAPPDATA%\AgentLinkGUI`
- 旧版本：`%LOCALAPPDATA%\AgentLinkApp`，本版保留。
- 共享记录：所选共享目录下 `jobs`；节点在线状态在 `nodes`。
- 完整源码直接包含在安装目录的 `main.py`、`app`、`source`，运行环境是普通文件，可检查、修改和替换。
- 卸载：关闭程序，删除“AgentLink GUI”桌面/开始菜单快捷方式和上述程序目录。历史目录可保留。

安装程序为本地构建的未签名文件，按当前用户安装，不要求管理员权限。不复制任何 Codex 登录凭据到共享目录或安装包。代码使用 GPL-3.0；依赖许可及源码获取地址见 `licenses`。

## 验证范围

源码中 `tests/test_system.py` 使用本机两个独立模拟 App Server，验证 A/B 均能发起、多轮、中文、流式事件、跨节点暂停/继续/停止、故障传递与重复执行保护。模拟测试不消耗模型额度。本版打包后还验证内置 Python/PyQt 启动和界面渲染。新的 GUI 在真实两台电脑和各自账号下的联调，仍需安装后完成；旧版本已经通过用户的真实双机验证。
