# AgentLink 0.3.10 整合说明

以冻结 0.3.9 运行源码为基础，恢复 0.3.4 的长任务能力；原 0.3.4 与 0.3.9 文件保留。

恢复内容：模型请求和 turn/start 等待不设 AgentLink 总时长上限；新讨论使用协议 2、expires=null；移除等待对方 20 分钟上限；恢复运行时长、最近事件、工具状态及静默提示；恢复未完成公开输出和对应本机任务 ID 导出；兼容协议 1/2 已完成历史；旧 timeout_seconds 字段迁移为 0，保留其余设置。

保留 0.3.9 的 Windows Job 宿主/执行进程保护、暂停创建和归属后恢复、清理失败留存句柄及共享 execution.lease、双方实例绑定、严格心跳时效和角色锁验证、请求编号和补充编号去重、旧轮次事件过滤、暂停发送边界、严格步骤与结果校验、小文件分块读取和场次会话映射清理。

新能力标志为 agentlink-execution-lease-v4。双方须更新后发起新任务；0.3.4/0.3.9 已完成历史可以迁移，但其节点不能参加新版本的活动讨论。旧程序不受新程序拒绝规则约束，因此不要混用活动节点。

长等待不等于忽略故障：明确接口错误、进程退出、用户停止/退出、对端实例或角色锁失效、共享持续故障仍会停止；非模型管理接口仍有通信超时。在线显示恢复本机单调时钟观察，执行准入继续保留严格时效要求，两机应保持系统时间同步。

整合时补修快速切换讨论的心跳滞后：前一场已终结但心跳尚未更新时，不再误判对方切换到其他活动场次。接收新场次即发布心跳；另一场仍为非终态时继续拒绝。

测试恢复 test_waiting.py；增加由 0.3.4 实际 Settings.save/Mailbox.create 生成的迁移样本、部分导出、旧事件不得伪造活动进展、旧能力拒绝及终态心跳切换检查。旧“本机调用限时”故障测试改为明确的上游超时错误，未删掉错误处理和不重发验证。

测试与构建证据在整合工作目录的 evidence 中。结果按实际日志记录，不能替代真实双机、真实 SMB 和各节点实际权限验收。新包独立交付，不自动替换正在运行的安装。
