# AgentLink 0.3.4 与 0.3.9 独立比较

日期：2026-09-11，节点 A。仅比较和测试，未修改、安装或替换任何生产程序，未发起真实模型调用。

**结论：0.3.9 增强了故障隔离和执行归属控制，但并非 0.3.4 的功能超集。0.3.4 的长任务支持被回退，设置迁移和协议 2 历史续接有可复现的兼容缺陷。不宜直接将该候选作为保持原功能的升级版。**

## 对象与证据

- 0.3.4：直接读取 `C:\AgentLink-GUI\dist\AgentLink-GUI-0.3.4` 内实际可运行目录的 `main.py`、`app/*.py`。
- 0.3.9：直接从 `C:\Users\infin\AppData\Local\AgentLinkGUI\workspace\cleanup-review-20260910\dist\AgentLink-GUI-0.3.9-Windows-x64.zip` 提取运行源码；ZIP SHA-256 为 `4e44c7fb7b120738bbe9ed1a829c754f086e62f769d603965a9f17252a89ef39`。
- `identity.json` 保存来源和逐文件 SHA-256，`diff/` 保存逐文件差异。测试只运行于本审查目录的隔离副本。主入口 main.py 字节相同；新增 app/process_job.py，其余差异见清单。
- 同一独立脚本对两个版本各执行 9 项行为观察，结果为 `0.3.4-independent-results.json`、`0.3.9-independent-results.json`。补充脚本对比旧流式事件和小文件内存分配，结果为 `*-supplement-results.json`。

- 未重跑整套 73 项、110 场耐久、全部硬崩溃或真实双机试验，不以既有报告中的数字作为本次执行结果。

## 相对 0.3.4 的改善和修复

| 项目 | 0.3.4 的问题或边界 | 0.3.9 行为与本次证据 |
|---|---|---|
| 延迟控制指令 | 点击旧场次的停止后、处理前切换所选场次，控制会使用处理时的场次，可能停止新任务 | 提交时绑定 job_id。同输入实测：0.3.4 停止新场次；0.3.9 只停止原场次。engine.py:79 |
| 补充内容去重 | 同一个 note_id 重放会再次追加 | 同编号同内容只追加一次；同编号不同内容拒绝；相同内容不同编号保留。独立对照中旧版 3 条、新版 2 条。engine.py:340 |
| 暂停的最后发送窗口 | 创建模型线程和最后一次处理事件时生效的暂停，未再次检查，可能穿过暂停发送请求 | 模型请求前再等待暂停解除。test_gaps.py 的屏障用例通过。engine.py:521 |
| 同一模型线程的旧事件 | 完成事件已有一定 turn_id 校验，但旧增量文本、工具事件、开始事件等仍可能污染当前轮次 | 按 turn_id 过滤，并先绑定 turn/start 响应再接纳先到事件。独立旧增量测试：0.3.4 答案出现 STALE-DELTA，0.3.9 保持空；相关回归通过。protocol.py:71、244 |
| 对端身份和执行权 | 普通在线/功能标志不能充分证明仍是原来的执行实例；重启后可能误接旧场次 | 校验能力时效、角色锁、owner 文件和双方实例绑定，在准入、发送和发布结果前复查；过期、退出、替换实例等定向回归通过。engine.py:166 |
| 异常遗留场次 | 释放讨论锁不等于旧执行者已退出，已领取无结果也不能等同未执行 | 新准入检查旧场次终态和独立 execution.lease；已领取未发布明确报“结果不确定”，不重发。test_gaps 和 cleanup_admission 通过。engine.py:85、250、734 |

| 清理失败后的跨节点新请求 | 仅讨论终态/讨论锁无法覆盖“清理失败但旧进程仍在”的窗口 | 清理失败保留共享执行锁及本机引用，阻止 A/B 新任务；确认清理成功后释放。2 个本机双服务、真实模拟进程场景通过。cleanup_admission.log |
| 步骤与结果校验 | 非法序号/输入可能被静默跳过，文件名与序号缺少一致性检查；对端结果仅检查少数字段 | 严查请求文件名、序号，并核对结果 job_id/index/step/role/状态/非空答案；相关请求校验回归通过。storage.py:370、engine.py:721 |

重复发起的基本冲突拒绝、请求编号去重、任务协议严格整数校验、有限 expires 校验，以及基本终态保护，在本次 0.3.4 基准中已经存在。不能把 0.3.2 的全部缺陷修复都算作 0.3.9 相对 0.3.4 的新增成果。

## 删除、回退和新增兼容问题

| 项目 | 0.3.4 | 0.3.9 | 判定 |
|---|---|---|---|
| 单次模型任务总时长 | 无 AgentLink 总时长上限；超时字段归零 | 默认 900 秒，设置界面 1–60 分钟。独立虚拟时钟模拟正常任务超过 900 秒：旧版完成，新版发送 turn/interrupt 并报超时 | 功能回退，已实测。protocol.py:332 |
| 等待对端及整场到期 | 无 20 分钟等待上限；新任务 protocol=2、expires=null | 对端等待恢复 1200 秒上限；整场 expires=(1+2×轮数)×1800 秒，一轮为 90 分钟；turn/start 响应恢复 90 秒超时 | 代码明确回退；本次未对所有计时器重新虚拟计时。engine.py:623、storage.py:298、protocol.py:322 |
| 旧设置迁移 | 保存/加载后 timeout_seconds=0 有效 | Settings.load 遇 0 抛 ValueError“单次超时应在 30 到 3600 秒之间”，而 main.py 在构建主窗口前调用它 | 升级阻塞缺陷，已实测配置加载。当前生产 settings.json 只核对了超时字段，为 900，不能据此断言这台电脑此刻必然启动失败；保存过 0.3.4 新设置的用户会受影响。storage.py:261 |
| 0.3.4 历史继续讨论 | 可续接已完成的协议 1/2 历史 | prepare_context 只接受协议 1；构造同一完整 protocol=2 历史，旧版承接成功，新版报缺失/不兼容 | 兼容缺陷，已实测。历史浏览入口仍保留，不能将“不能续接”说成“删除历史”。context.py:64 |
| 运行状态提示 | 显示运行时长、最近事件时间、工具是否仍在运行、静默但进程仍在等信息；向对端同步 execution | 移除 activity_snapshot、execution 心跳字段及 render_execution/状态标签 | 确认删除。界面仍保留回答流、工具事件及运行日志，这些不是同一个功能。ui.py.diff |
| 未完成讨论导出 | 将 live 内容及本机任务 ID 作为“未完成输出”导出 | 只导出已保存 turns；独立 GUI 导出观察中，部分输出和对应任务 ID 均不再出现 | 确认删除/回退。完整已完成讨论导出仍在。ui.py:461 |
| 跨机时钟容忍 | 在线变化使用本机单调时钟跟踪心跳变化 | 删除该跟踪方法，能力校验重新要求墙上时间差约在 -1 到 12 秒内 | 代码确认更依赖两机时钟一致；本次未进行真实时钟偏差实验。engine.py:166 |
| 回归测试与使用说明 | 带有 test_waiting.py 和完整无时限说明 | 0.3.9 包未包含 test_waiting.py，无时限使用说明被移除；README 标题是 0.3.9，升级步骤仍写 0.3.8 包名和 v0.3.8 | 测试覆盖/文档回退，包内直接核对 |

从 diff 和行为看，0.3.9 没有整合 0.3.4 的长任务改动。这是代码事实；不推定开发者有意删除，也不以版本号递增推定完整继承。

## 仍保留的主要功能

A/B 任意一方发起、多轮评审、双列增量回答、公开摘要、工具事件、历史浏览、协议 1 已完成历史续接、新建讨论、复制最终答复、已完成记录 TXT/Markdown 导出、实施交接文件、Codex 任务 ID、导入旧 TXT、角色选择、本机独立账号和工具配置、沙盒设置、暂停/继续/停止/补充入口均仍在。大部分由代码入口确认；本次没有把每一个入口全部重新做 GUI 端到端测试。

0.3.9 的更严格准入会拒绝旧版本、无新能力标志、陈旧心跳、实例变化、未结束旧场次或未确认进程清理状态。这些是故障保护带来的行为收紧，不是删除 A/B 协作能力。新版本拒绝旧节点不能约束仍运行的旧版发起者，不能声称所有混版情形零请求。

## 建议与边界

先保留 0.3.9 的进程归属、执行锁和事件校验修复，恢复 0.3.4 的无时限等待、活动同步、部分输出导出以及协议 2 兼容；增加真实 0.3.4 Settings.save 输出和协议 2 完整历史的升级回归，再作为新的整合候选。

32 个定向回归通过说明所覆盖分支有效，不能抵销独立对照中已复现的回退，也不能证明真实双机/SMB/权限验收完成。本次没有修改产品；原安装和冻结候选保持原样。
