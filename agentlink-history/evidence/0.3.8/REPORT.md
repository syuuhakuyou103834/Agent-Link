# 0.3.8：采纳 B 第 1 轮核对意见后的修复与证据

采纳四项核对要求。补查确认 0.3.7 的 CloseHandle 错误路径缺口，已修复并形成 0.3.8；没有把 B 未执行测试改判为通过。A 同意本轮发现的修改已完成，完整双机验收及双方最终同意仍未成立。

## 新发现与修改

0.3.7 注入 CloseHandle=FALSE／WinError 5 后，未报错且清空归属句柄（evidence/baseline-close-failure.json）。0.3.8 清理先终止服务 Job，查询活动进程为零，再检查关闭返回值；失败保留句柄并抛出带原始异常的清理错误。cleanup_pending 阻止 RPC 新请求及服务准入；成功执行显式清理后允许重新连接。依据微软 [Job 活动进程计数](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_accounting_information) 与 [查询接口](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-queryinformationjobobject)。

终止失败、查询失败、关闭失败及等待超时四类测试通过。前三类均验证句柄保留、错误提示、零模型请求、准入被拒绝、清理恢复后可连接。并非宣称实际 Windows 已发生上述 API 故障；这是针对遗漏错误分支的故障注入复现。
