### 业务目标

用户只需在一个对话框里表达问题、任务和工作目录，无需先判断应使用“文字讨论”还是“项目代码审查”。软件负责先厘清任务，再按授权范围协调 A 执行、B 独立审查，展示过程、证据和结果。

取消的是用户手动选择模式和填写项目表单的负担；原有目录边界、源码快照、独立测试、历史记录和中断恢复能力继续保留。

### 对话轮数与结束条件

| 编号 | 要求 |
|---|---|
| BR-017-21 | 主界面把“总调用数”改为“对话轮数”。A 提交一次正式成果、B 完成一次正式审查，构成一轮。 |
| BR-017-22 | 最后 A 的结果总结不额外计一轮。A→B→A 最终总结，在 A/B 只协作一次时显示 1 轮。 |
| BR-017-23 | 用户与 A 或 B 无论进行多少次澄清、问答、补充，均不计正式协作轮数；完成后的 B 补审对话也不计。 |
| BR-017-24 | 中断或部分输出不算该轮完成。B 额度耗尽时显示当前轮未完成，恢复并完成后才计入；不会因重启或恢复重复计数。 |
| BR-017-25 | 正式 A/B 协作默认最多 3 轮，可由用户在消息中指定其他上限，不再要求事先操作轮数控件。澄清没有强制轮数，这不等于正式协作无限循环。 |
| BR-017-26 | 达成验收条件并由 A/B 确认后提前结束。达到上限仍有分歧，由 A 汇总分歧、证据和待裁决事项，交用户决定，不冒称审查通过。 |
| BR-017-27 | 后台保留真实模型请求记录和失败尝试，用于额度与故障排查。对话轮数不是计费请求数；不能据界面轮数宣称实际只调用过相同次数的模型。 |

依据：Q7 的用户修订、Q8、Q9，以及用户对最终整体方案的确认。

### 标准用户流程

1. 用户在 A 端直接输入任务和目录。例如：“工作目录是 C:\Work\Demo，修复恢复后丢失补充要求的问题。”
2. A 使用 grill-me，必要时只读检查目录，询问目标与约束，形成简短任务说明。
3. 用户确认开始；如果 B 未就绪，任务保存为等待状态。
4. B 就绪后 A 执行限定任务，交付快照，B 独立审查／测试。
5. 需要修改时，在范围和轮数上限内继续 A/B 协作；通过、阻塞或达到上限时给出真实结论。
6. A 最后总结完成项、验证证据、遗留问题和未验证事项。
7. 用户继续输入则承接上下文；B 可以补审；新建独立对话仅由 A 发起。

讨论类任务经过相同澄清和确认入口，但任务说明应明确只讨论，不产生项目修改。

### 验收场景

下表保存原验收要求。0.3.17 已提供对应实现，本机证据和剩余真实环境验收逐项列于 `RELEASE-0.3.17.md`；不能将本机验证扩大为双机验收通过。

| 编号 | 场景 | 预期 |
|---|---|---|
| AC-017-01 | 新建任务，不触碰任何模式控件 | A 端单一输入即可开始澄清；B 无新任务发起能力。 |
| AC-017-02 | 消息中提供工作目录；另一个任务只问知识 | 前者确认、沿用该目录；后者不强制创建项目。 |
| AC-017-03 | 用户只要求讨论，A 只读检查后澄清 | 不修改项目，不产生有副作用的测试；确认前不正式执行。 |
| AC-017-04 | 用户确认实现任务，A 交付、B 审查 | A 按范围修改，B 可独立读取快照，源码只读，测试输出隔离。 |
| AC-017-05 | 用户与 A 多次澄清，再有一次 A/B 协作和 A 总结 | 主界面显示 1 轮；后台请求记录仍完整。 |
| AC-017-06 | A/B 一次未通过、一次修订后通过 | 显示 2 轮，提前结束，无需凑满默认 3 轮。 |
| AC-017-07 | 用户在 B 端补充修改要求 | B 接收并带用户来源转交 A；B 不修改源码、不新建任务。 |
| AC-017-08 | A/B 两端要求相互矛盾 | 暂停后续步骤，显示冲突，等待用户裁决。 |
| AC-017-09 | 达到轮数上限仍不能通过 | A 总结分歧及待处理事项，不能显示验收通过或无上限继续。 |
| AC-017-10 | 任务完成后在 A 端继续输入新增要求 | 保留目录和历史，只澄清新增任务；不要求手工选承接历史。 |
| AC-017-11 | 完成后 B 补审发现新问题 | 保留原完成记录，追加补审证据，不增轮数，不自动启动 A 修改。 |
| AC-017-12 | B 离线时 A 输入并确认任务 | A 可澄清，正式执行等待 B；B 就绪后不重复澄清。 |
| AC-017-13 | 澄清、A 执行或 B 审查阶段中断后恢复 | 保留用户约束、目标节点、阶段和计数，不重跑已完成部分，不自动重发不确定请求。 |
| AC-017-14 | 查看历史、恢复任务、导出证据及部署两端 | 原有必要能力保留；详情有明确入口，实际结果按本机／双机证据分别报告。 |

### 已取代的方案与范围边界

- Q2 最终采用“用户在消息中输入目录”，取代前置项目表单和目录选择步骤。
- Q10 最终采用“本机输入交给本节点”，取代默认发 A、使用 @A/@B 的建议。
- Q12 最终采用“只有 A 发起任务”，取代允许 B 发起、再转 A 澄清的建议。
- 澄清阶段不设强制提问轮数；正式协作仍默认最多 3 轮。两者不得混为一谈。
- 不增加自动审批、完全访问或自动扩大文件范围。B 仍不能修改 A 源码或访问 A 的其他路径／软件。
- 本版没有新增增量快照、GitHub 自动同步、账号额度重置或其他未经确认的功能。
- 本文描述经确认的业务行为，不强制采用特定内部模块划分；实现仍需保持权限、快照与状态一致性。
