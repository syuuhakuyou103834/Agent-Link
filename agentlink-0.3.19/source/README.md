# AgentLink 0.3.19 · 心跳中断与接续修复

以 0.3.18 为基线，修复心跳中断被误分类为取消、导致无法继续的问题；保留原有长对话与证据交付能力。保留“你 / A / B”单一时间线：A 负责执行，B 独立审查。新增任务先由 A 使用内置 grill-me 澄清，用户确认以后才执行。

## 从 0.3.18 升级与恢复

两端退出旧程序，分别解压本版到新目录并运行 AgentLink.exe。沿用各自设置和原共享目录；不要删除原任务、源码快照或用户数据。

对于 0.3.18 因“对端实例失效”中断但原始记录被写成取消的场次，程序会核对原停止指令与节点错误证据。两端升级后在原中断对话输入“继续”，继承已完成的 A 结果，从 B 未完成步骤接回。升级本身不会发出模型请求。主动停止、证据缺失或不匹配的记录仍不允许恢复。不要点“停止任务”来升级。

心跳异常现在显示发生节点、时间差、失败原因和发送状态；在线徽标使用相同的时间有效性规则，实例绑定与角色锁仍独立检查。具体升级步骤见 DEBUG-0.3.19.md。

对于 0.3.17 显示“上下文超过传输上限，未发送模型请求”的中断，在两端均连接 0.3.19 后选中原任务，输入“继续”。未处理消息保留原目标节点；已经完成的 A/B 步骤不会重跑。节点重启后使用关联恢复记录继承已完成结果，不覆盖原执行记录。升级本身不会自动发送请求。无法确认原任务、执行者或范围时仍会阻塞。

完整记录与模型输入分开：工具输出、重复 answer/blocks 不再嵌入对话正文；本机生成带 SHA-256 的只读证据文件和索引。B 在自己的电脑接收、核验并保存这些记录，不通过 A 的本地路径读取。工具证据是软件此前捕获的记录，不等于 B 已独立验证。

长对话接近预算时，较早的普通答复可转为明确的完整正文文件引用；用户要求、未处理消息、未决正式审查、最近四条消息保留在输入中。没有模型自动概括，没有静默截断原文。模型应按需读取外置正文，不能声称已读未打开的证据。

“展开详情 → 任务与快照”显示本机发送规模、证据索引、外置消息序号和阻塞原因。限制仍为 280,000 字符及 950,000 JSON 字节，两者均须满足；不是 token 数，也不等于模型自身上下文窗口。必要正文仍过大时不会发送。需要用户整理交接说明后另建任务时，应保留原任务再明确停止，并在新任务中重述目标、权限、未决事项和证据位置。本版没有新增自动摘要服务。

## 开始使用

1. A、B 两台电脑都解压本版便携包，在各自电脑运行 AgentLink.exe，继续使用原来的 B 端共享通信目录。局域网工作不依赖 GitHub。
2. 只有 A 端可以新建对话。在主输入框写任务；涉及文件时写明 **A 电脑上已存在的具体项目目录**，建议目录单独一行或用反引号包围。例如：

   工作目录：`C:\Work\Demo`
   请只读审查这个项目，先不要修改代码。

3. A 可以先只读检查和澄清，即使 B 尚未连接。任务清晰后，A 给出目标、目录、文件行为、修改范围、验收条件、B 审查内容和轮数上限。
4. 阅读任务说明后回复“开始”。提前发送或针对旧说明的确认不生效。B 未就绪时保存为“等待 B”。
5. B 就绪后，A 执行、B 审查，A 最后汇总。B 会自动显示当前新任务，也可在左侧选择历史任务。

## 任务与消息

- 不再选择“文字讨论/项目代码审查”，也不填写项目表单。普通问答无需目录。
- 明确只讨论、解释或分析时不修改项目；只读审查可以将测试输出写入独立目录；明确要求实现或修复时才允许 A 在确认的项目内修改。
- 主输入框永远交给本机节点：A 电脑的输入交 A，B 电脑的输入交 B。运行中可补充方向；下一正式步骤会等待补充消息处理完毕。
- B 收到修改要求时保留用户来源并转交 A。B 没有源码修改权。范围变化需 A 更新任务说明并重新取得确认；两端要求冲突时暂停并等待裁决。
- 完成后在 A 端继续输入会保留当前对话上下文，新增任务进行必要澄清。B 可补充只读审查，不增加正式轮数，也不自动启动 A 修改。
- 点击“新建对话”开启独立上下文。旧版记录可查看、导出；如需将旧版任务作为新任务材料，在 A 端新建对话并粘贴需要承接的内容。

## 轮数、暂停与中断

A 提交成果、B 完成审查才算 **1 轮**。A 最后的总结不计轮数；用户与 A/B 的澄清、问答和补充不计轮数。默认最多 3 轮，用户可在消息中指定其他上限（当前支持 1–99）。提前达成一致可以结束；上限到达仍有分歧，由 A 汇总交用户裁决。

点击“暂停”后，当前调用结束即暂停后续步骤。在同一输入框输入“继续”恢复。额度耗尽、进程退出等中断会保留已完成结果、部分输出和请求台账；修复环境后明确输入“继续”，继续未完成步骤并接回原流程。恢复可能发送新的模型请求，**不会恢复账号额度**。

失败场次保持原状，恢复使用关联子场次并继承已完成步骤；已发送但状态不确定的请求不会自动重发。无法确认原本机范围或会话归属时会阻塞，需要查看错误后处理。停止任务不会自行复活。

## 源码交付与权限

保留 0.3.16 的完整快照：A 打包全部可交付项目文件，生成清单与 SHA-256，最后发布 ready；B 在本机校验和解包。B 的源码/原测试只读，正式审查的测试输出写独立目录。不会开放 A 的其他路径或软件。

沿用排除规则：常见凭据（含 .env*）、版本控制目录和依赖缓存不交付；排除项可查。排除规则不能识别写入普通源码的所有秘密。符号链接、目录联接、硬链接等不随快照交付；缺失依赖明确报告，不自行扩大权限。

每次新任务的模型会话使用明确的文件权限；禁用外部应用、MCP、Web 搜索和权限升级。澄清只读；正式修改仅授予确认目录写权限。旧设置保留用于历史兼容，不能覆盖新任务权限。

## 记录位置与交付

- `conversations/<对话ID>/conversation.json`：共享对话、用户来源、说明/确认、消息顺序、聊天请求台账；本机也保存缓存。
- `jobs/<场次ID>/`：执行请求、模型请求台账、原始结果、部分输出与失败证据。
- `jobs/<场次ID>/artifacts/<哈希>/`：源码 ZIP、manifest.json 和 ready.json。
- 本机 `runs/<场次ID>/`：实际本机范围、清单及缓存；`project-tests/`：独立测试输出。
- 展开详情可查看快照、测试工具事件、公开摘要、节点能力和日志；主界面可复制、导出完整记录和本机 Codex 任务 ID。

对话轮数不等于模型计费请求数；澄清和补充也会使用对应节点的额度。收到完整快照不等于已经完整阅读或执行测试，结果必须以实际证据为准。

源码启动：`python main.py`；隔离数据目录：`python main.py --data-dir C:\AgentLink-Test`。
本机回归：`python tests/run_release_checks.py`；真实 RPC 权限预检（不调用模型）：`python tests/check_unified_preflight.py`。

业务要求见 docs/BUSINESS-REQUIREMENTS.md；完整交付报告 RELEASE-0.3.19.md、故障说明 DEBUG-0.3.19.md 与开发日志 DEVELOPMENT-LOG-0.3.19.md 随包提供。
